ICT 2102 – Web Development

Week 7: Responsive Web Design

Practical teaching guide: learn each core concept step by step.

1. Practical learning outcomes

By the end of this practical, students should be able to:

  • Explain why websites must adapt to different screen sizes.
  • Set the viewport correctly in an HTML page.
  • Replace fixed-width layouts with flexible layouts.
  • Make images fit within their containers.
  • Use CSS media queries to adapt a page at different widths.
  • Create responsive navigation and card layouts.
  • Test a webpage at mobile, tablet, and desktop sizes.
Before starting: Use an existing HTML/CSS practice website or create a folder named week7-responsive containing index.html and style.css. Save each code example, refresh the browser, and compare the result before and after the change.

2. Understand Responsive Web Design

Responsive Web Design (RWD) is an approach to designing websites so that their layout and content adjust to available screen space. A responsive page should remain readable and usable on a phone, tablet, laptop, and desktop monitor.

Demonstration: fixed versus responsive width

First, try this fixed-width rule. It may make a page wider than a phone screen.

.container {
  width: 1000px;
  margin: 0 auto;
}

Replace it with a flexible container:

.container {
  width: 90%;
  max-width: 1000px;
  margin: 0 auto;
}

What the code means: the container uses 90% of the available width, but it will not grow beyond 1000 pixels. The automatic margins centre it.

Try it: resize the browser window. Observe how the container becomes narrower on a small screen while keeping a maximum width on a large screen.

3. Set the viewport meta tag

The viewport tells mobile browsers how to size the page to the device's screen. Place this tag inside the <head> section of every HTML page you are testing.

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Example HTML starter

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Responsive Practice</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main class="container">
    <h1>Responsive Web Design</h1>
    <p>This page will adapt to different screen sizes.</p>
  </main>
</body>
</html>

The viewport tag does not make a page responsive by itself. It works together with flexible CSS, suitable images, and media queries.

4. Make images responsive

Images with fixed widths can overflow their containers on small screens. Add this rule to style.css:

img {
  max-width: 100%;
  height: auto;
  display: block;
}
  • max-width: 100% prevents the image from exceeding its container.
  • height: auto preserves the image's proportions.
  • display: block removes the small inline gap that can appear below an image.

Try it: add an image to your HTML page, then resize the browser. Confirm that the image shrinks with its container instead of causing horizontal scrolling.

Use a valid image file path, for example <img src="images/sample.jpg" alt="A sample demonstration">. The alt text describes the image for users who cannot see it.

5. Use media queries

A media query applies CSS rules only when a condition is true, such as when the viewport is narrower than a chosen breakpoint.

Basic example

body {
  font-size: 18px;
}

@media (max-width: 600px) {
  body {
    font-size: 16px;
  }
}

On screens up to 600 pixels wide, the body text changes to 16 pixels. On wider screens, it remains 18 pixels.

Practice task

  1. Set the page background to a light colour in the normal CSS rule.
  2. Add a media query for a viewport of 600 pixels or less.
  3. Change the background or heading size inside the media query.
  4. Resize the browser to see when the change takes effect.

Choose a breakpoint where the content needs to change, rather than relying only on device names.

6. Build responsive navigation

A navigation bar may fit on one line on a desktop but become crowded on a phone. Flexbox and a media query can make it wrap or stack vertically.

HTML

<nav class="navigation">
  <a href="index.html">Home</a>
  <a href="about.html">About</a>
  <a href="services.html">Services</a>
  <a href="contact.html">Contact</a>
</nav>

CSS

.navigation {
  display: flex;
  justify-content: center;
  gap: 1rem;
  flex-wrap: wrap;
  padding: 1rem;
}

.navigation a {
  padding: 0.5rem 0.75rem;
  text-decoration: none;
}

@media (max-width: 600px) {
  .navigation {
    flex-direction: column;
    align-items: stretch;
    gap: 0.25rem;
  }

  .navigation a {
    display: block;
  }
}

Observe: on a wide screen, links can appear in a row. On a narrow screen, they stack vertically and are easier to tap.

7. Create a responsive card grid

CSS Grid is useful for displaying items such as services, books, menu items, or course cards. The number of columns can change as the viewport narrows.

HTML

<main class="container">
  <h1>Featured Items</h1>
  <div class="card-grid">
    <article class="card"><h2>Item One</h2><p>Description of item one.</p></article>
    <article class="card"><h2>Item Two</h2><p>Description of item two.</p></article>
    <article class="card"><h2>Item Three</h2><p>Description of item three.</p></article>
  </div>
</main>

CSS

.container {
  width: 90%;
  max-width: 1000px;
  margin: 0 auto;
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1rem;
}

.card {
  padding: 1rem;
  border: 1px solid #cbd5e1;
  border-radius: 8px;
  min-width: 0;
}

@media (max-width: 800px) {
  .card-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (max-width: 500px) {
  .card-grid {
    grid-template-columns: 1fr;
  }
}

Test: at a wide viewport, cards appear in three columns; at 800 pixels or below, they appear in two columns; at 500 pixels or below, they appear in one column.

8. Practise a mobile-first layout

Mobile-first design starts with the simplest layout for small screens. CSS rules are then added for wider screens.

/* Base styles: small screens first */
.content-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

/* Wider screens */
@media (min-width: 600px) {
  .content-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 1000px) {
  .content-grid {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}

The default is one column. From 600 pixels, the layout uses two columns. From 1000 pixels, it uses three columns.

Student practice

  1. Start with a one-column layout.
  2. Add a breakpoint at 600 pixels for two columns.
  3. Add a breakpoint at 1000 pixels for three columns.
  4. Test at widths below, between, and above those breakpoints.

9. Test and debug responsiveness

  1. Open the page in a browser such as Chrome or Firefox.
  2. Open Developer Tools using the browser menu or F12.
  3. Enable the device toolbar or responsive design mode.
  4. Test a narrow phone width, a tablet-sized width, and a desktop width.
  5. Check navigation, images, cards, headings, buttons, and paragraphs.
  6. Return to the CSS and fix any overflow or crowded content.

Responsive design checklist

  • Viewport meta tag is present.
  • Containers use flexible widths and sensible maximum widths.
  • Images fit inside their containers.
  • Media queries change layout where necessary.
  • Navigation links remain readable and usable.
  • Text does not become too small or overlap.
  • There is no unnecessary horizontal scrolling.
  • Buttons and links can be comfortably selected on a touch screen.

10. Consolidation questions

  1. What is Responsive Web Design, and why is it important?
  2. What does the viewport meta tag do?
  3. Explain the difference between a fixed-width container and a flexible container.
  4. Why are max-width: 100% and height: auto useful for images?
  5. What is a CSS media query? Give one example.
  6. Explain the difference between a mobile-first approach and a desktop-first approach.
  7. How can Flexbox or CSS Grid help create responsive layouts?
  8. Describe how you would test a webpage at different viewport sizes.
